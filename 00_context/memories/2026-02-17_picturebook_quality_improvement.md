# 絵本脚本の品質改善

**日時**: 2026年2月17日
**問題**: 生成された絵本が「感想文のような脚本」
**原因**: 文字数制限が厳しすぎる + UIの表示バグ

---

## 問題の詳細

### ユーザーからのフィードバック

```
📄 Page 1
テキスト:
ポラーは我が家の愛犬です。毎朝の散歩が日課です。

画像プロンプト:
なし
```

**問題点**:
1. ✅ 画像プロンプトが実際には存在するのに「なし」と表示（UIバグ）
2. ❌ 1ページあたり40〜90字と短すぎて深みがない
3. ❌ 具体的な情景描写がない（「毎朝の散歩」は抽象的）
4. ❌ Showing技法が使われていない（説明的な文章）
5. ❌ 五感描写がない
6. ❌ 内的独白がない

**ユーザーの評価**: 「この感想文のような脚本はどうして？」

---

## 原因分析

### 1. UIの表示バグ

**問題のコード** (`test_ui_v3.html` line 1307):
```javascript
${page.image_prompt || 'なし'}
```

**実際のデータ構造**:
```json
{
  "page_number": 1,
  "text": "...",
  "illustration_prompt": "A cheerful dog...",  // ← これが正しいフィールド名
  "illustration_style_note": "温かみのあるスタイル"
}
```

→ UIが `image_prompt` を参照しているが、実際は `illustration_prompt` というフィールド名

### 2. 文字数制限が厳しすぎる

**スキーマ** (`memoir_editor_api.py` line 311):
```python
"text": {"type": "string", "description": "40〜90字の短文（です・ます調）"}
```

**プロンプト** (line 1012):
```
2. 1ページの文章は短文（40〜90字目安）
```

→ 40〜90字では1〜2文しか書けず、具体的な情景描写や感情表現が不可能

### 3. Showing技法の指示が不十分

プロンプトに「Showing（見せる）」は記載されているが、具体例が少なく、AIが実際にどう書けばいいか理解しづらい。

---

## 修正内容

### 1. UIの表示バグ修正

**ファイル**: `tools/test_ui_v3.html`

```javascript
// 修正前
${page.image_prompt || 'なし'}

// 修正後
${page.illustration_prompt || 'なし'}

<strong>スタイル:</strong>
${page.illustration_style_note || 'なし'}
```

### 2. 文字数制限の大幅緩和

**ファイル**: `tools/memoir_editor_api.py`

#### スキーマ変更 (line 311):
```python
// 修正前
"text": {"type": "string", "description": "40〜90字の短文（です・ます調）"}

// 修正後
"text": {"type": "string", "description": "200〜400字の文章（です・ます調、情景描写と感情を含む）"}
```

#### プロンプト変更 (line 1010-1020):
```
// 修正前
2. 1ページの文章は短文（40〜90字目安）

// 修正後
2. **1ページの文章は200〜400字**（情景描写、感情、内的独白を含む読み応えのある内容）
6. **Showing技法を活用**：説明ではなく、具体的なシーンで見せる
7. **五感描写を含める**：視覚、聴覚、嗅覚、触覚、味覚のうち2〜3つ
```

### 3. Showing技法の具体例追加

**ファイル**: `tools/memoir_editor_api.py` (line 955-962)

```markdown
## ✅ 優先事項

- **Showing（見せる）**: 感情を行動・表情で表現
  - ❌ Telling: 「嬉しかったです」
  - ✅ Showing: 「ポラーの尻尾が激しく揺れ、私の顔を何度も舐めてきました」

- **具体的な情景**: 時間・場所・五感
  - ❌ 抽象: 「散歩に行きました」
  - ✅ 具体: 「朝7時、まだ冷たい空気の中、ポラーのリードを引くと小さく鳴いて喜びました」

- **内的独白**: 心の声を織り交ぜる
  - 「本当にこれでよかったのか、ふと不安がよぎりました」

- **象徴的なオブジェクト**: 繰り返し登場する物
  - 例：お気に入りのおもちゃ、散歩コース、特定の場所

- **葛藤**: ドラマの核心
  - 単なるハッピーストーリーではなく、不安・迷い・困難を描く

- **余韻**: すべてを説明しない
  - 最後は余韻を残す終わり方（「〜なのかもしれません」）
```

朝7時。まだ薄暗い玄関で、ポラーはリードを見つけると小さく鳴きました。
尻尾を激しく振りながら、私の足元をくるくると回ります。
「今日も元気だね」そう声をかけると、ポラーは嬉しそうに私の手を舐めてきました。

冷たい空気が頬に触れる中、いつもの散歩道を歩き始めます。
ポラーは小さな体で一生懸命に歩き、時々立ち止まって匂いを嗅いでいます。
こんな何でもない日常が、実はとても大切な時間なのだと、ふと思いました。

でも、いつまでこの日々が続くのだろう。
そんな不安が、心の片隅にいつもありました。

**改善点**:
- ✅ Showing技法（尻尾を振る、くるくる回る）
- ✅ 五感描写（冷たい空気、匂い）
- ✅ 内的独白（「ふと思いました」「そんな不安が」）
- ✅ 具体的な情景（朝7時、薄暗い玄関）

## 文字数変更の設計判断

### 検討した選択肢

1. **絵本モード**: 40〜90字/ページ（子供向け）
2. **自分史モード**: 200〜400字/ページ（大人向け）
3. **可変モード**: ユーザーが選択

### 選択した理由

**200〜400字/ページを採用**:
- ユーザーの事業は「大人向け自分史絵本」がメイン
- 「感想文のような」という批判から、読み応えが必要
- B2B顧客（鈴木自工、かんぽ生命）は大人向けストーリーを期待
- 子供向けは別途「子供向けパーソナライズ絵本」として提供

### 今後の拡張案

ジャンル別に文字数を変える：
```python
if genre == "kids":
    char_per_page = "40〜90字"
elif genre == "family":
    char_per_page = "150〜250字"
elif genre == "business" or genre == "pet":
    char_per_page = "200〜400字"
```
