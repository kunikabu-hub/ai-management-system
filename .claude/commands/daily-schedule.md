# daily-schedule

今日の最適なスケジュールを生成し、DAILY.mdに書き込みます。

## 実行内容

このコマンドは、以下のステップで本日の最適なスケジュールを作成します：

1. **Google Calendarから今日の予定を取得**
2. **DAILY.mdから昨日の未完了タスクを確認**
3. **プロジェクトフォルダを確認し、期限の近いタスクを把握**
4. **タスクを「緊急度×重要度」と「認知負荷」で分類**
5. **15分刻みの工程表を生成**
6. **DAILY.mdに本日の工程表を書き込む**

---

## ステップ1: Google Calendarから今日の予定を取得

まず、Google Calendar APIを使って今日の予定を取得します。

**実行内容**:
- 今日の日付（YYYY-MM-DD形式）を確認
- Google Calendar APIを使用して本日の予定を取得
- 予定のタイトル、開始時刻、終了時刻、場所、説明を取得

**注意事項**:
- Google Calendar APIの認証が必要です（Google Drive APIと同じOAuth2認証を使用）
- もしGoogle Calendar APIが有効化されていない場合は、ユーザーに通知してください

**期待する出力例**:
```
今日の予定 (2026-02-12):
- 10:00-11:00: 鈴木自工MTG (オンライン)
- 14:00-15:00: ナック提案準備
- 16:00-17:00: 開発定例
```

---

## ステップ2: DAILY.mdから昨日の未完了タスクを確認

DAILY.mdファイルを読み込み、昨日の日付のセクションから未完了タスクを抽出します。

**実行内容**:
1. DAILY.mdを読み込む
2. 昨日の日付（YYYY-MM-DD形式）のセクションを探す
3. チェックボックス `[ ]` がついているタスクを未完了タスクとして抽出
4. すでに完了している `[x]` タスクは除外

**期待する出力例**:
```
昨日の未完了タスク:
- [ ] ナック提案資料の作成
- [ ] ペット絵本企画の壁打ち
- [ ] かんぽ生命MTG議事録のまとめ
```

---

## ステップ3: プロジェクトフォルダを確認し、期限の近いタスクを把握

`03_projects/` ディレクトリ内のプロジェクトファイルを確認し、期限が近いタスクを抽出します。

**実行内容**:
1. `03_projects/` ディレクトリ内のMarkdownファイルを全て読み込む
2. 各ファイルから以下の情報を抽出:
   - タスクリスト（チェックボックス形式）
   - 期限（`期限:`, `deadline:`, `due:` などのキーワード）
   - 優先度（`優先度:`, `priority:` などのキーワード）
3. 今日から7日以内に期限が来るタスクを抽出
4. 優先度が高いタスクを優先

**期待する出力例**:
```
期限の近いタスク:
- [鈴木自工] 管理画面のワイヤーフレーム確認 (期限: 2026-02-14, 優先度: 高)
- [ナック] 提案資料の提出 (期限: 2026-02-13, 優先度: 高)
- [ペット絵本] AI壁打ちのまとめ (期限: 2026-02-15, 優先度: 中)
```

---

## ステップ4: タスクを「緊急度×重要度」と「認知負荷」で分類

収集したタスクを以下の軸で分類します：

### 緊急度×重要度マトリクス（アイゼンハワーマトリクス）

| 緊急度＼重要度 | 重要 | 重要でない |
|--------------|------|-----------|
| **緊急** | 🔴 第1象限: すぐやる | 🟡 第3象限: 委譲・短時間処理 |
| **緊急でない** | 🟢 第2象限: 計画的に実施 | ⚪ 第4象限: やらない |

### 認知負荷の分類

- **高負荷**: 深い思考、創造性、集中力が必要（企画立案、戦略策定、複雑な分析）
- **中負荷**: ある程度の集中力が必要（資料作成、ミーティング準備、レビュー）
- **低負荷**: ルーチン作業、単純タスク（メール返信、ファイル整理、簡単な確認作業）

**実行内容**:
1. 各タスクを緊急度（期限、依存関係）で評価
2. 各タスクを重要度（事業への影響度）で評価
3. 各タスクを認知負荷（必要な集中力）で評価
4. 優先順位を決定

**期待する出力例**:
```
タスク分類:

🔴 第1象限（緊急かつ重要）- 高負荷:
- ナック提案資料の作成 (期限: 明日, 認知負荷: 高)

🔴 第1象限（緊急かつ重要）- 中負荷:
- 鈴木自工MTG準備 (期限: 今日10:00, 認知負荷: 中)

🟢 第2象限（重要だが緊急でない）- 高負荷:
- ペット絵本企画の壁打ち (期限: 2/15, 認知負荷: 高)

🟡 第3象限（緊急だが重要でない）- 低負荷:
- かんぽ生命MTG議事録のまとめ (期限: 今日, 認知負荷: 低)
```

## ステップ5: 15分刻みの工程表を生成

最適な時間配分を考慮して、15分刻みのスケジュールを生成します。

**考慮事項**:
1. **認知負荷の配置**:
   - 午前中（9:00-12:00）: 高負荷タスクを配置（集中力が高い）
   - 午後前半（13:00-15:00）: 中負荷タスクを配置
   - 午後後半（15:00-18:00）: 中〜低負荷タスクを配置
   - 夕方（18:00-19:00）: 低負荷タスクを配置

2. **休憩の挿入**:
   - 90分集中 → 15分休憩（ポモドーロテクニックの応用）
   - 昼休憩: 12:00-13:00

3. **バッファ時間**:
   - 予期せぬ事態に備えて、各タスク間に15分のバッファを確保

4. **Google Calendarの予定を優先**:
   - カレンダーの予定をベースに、空き時間にタスクを配置

**実行内容**:
1. Google Calendarの予定を時間軸に配置
2. 空き時間を特定
3. 高負荷タスクを午前中の空き時間に配置
4. 中負荷タスクを午後前半に配置
5. 低負荷タスクを午後後半・夕方に配置
6. 休憩時間を適切に挿入
7. 15分刻みのタイムテーブルを生成

**期待する出力例**:
```
2026年2月12日（水） - 本日のスケジュール

09:00-09:15 📧 メールチェック・返信 (低負荷)
09:15-10:00 📝 ナック提案資料の構成検討 (高負荷)
10:00-11:00 🚗 鈴木自工MTG (Google Calendar)
11:00-11:15 ☕️ 休憩
11:15-12:00 📝 ナック提案資料の作成 (高負荷)
12:00-13:00 🍱 昼休憩
13:00-13:30 📋 鈴木自工MTG議事録まとめ (中負荷)
13:30-14:00 📝 ナック提案資料の最終確認 (中負荷)
14:00-15:00 🏢 ナック提案準備 (Google Calendar)
15:00-15:15 ☕️ 休憩
15:15-16:00 💭 ペット絵本企画の壁打ち (高負荷)
16:00-17:00 👥 開発定例 (Google Calendar)
17:00-17:15 ☕️ 休憩
17:15-17:45 📄 かんぽ生命MTG議事録のまとめ (低負荷)
17:45-18:00 📂 ファイル整理・明日の準備 (低負荷)
```

2. ✅ 昨日の未完了タスクが含まれているか

4. ✅ 高負荷タスクが午前中に配置されているか

## Google Calendar API設定（初回のみ）

Google Calendar APIを使用するには、以下の設定が必要です：

1. **Google Cloud ConsoleでGoogle Calendar APIを有効化**:
   - https://console.cloud.google.com/
   - 「APIとサービス」→「ライブラリ」
   - 「Google Calendar API」を検索して有効化

2. **OAuth2スコープの追加**:
   - Google Drive APIと同じOAuth2認証を使用
   - スコープに `https://www.googleapis.com/auth/calendar.readonly` を追加

3. **トークンの再取得**:
   ```bash
   python3 tools/get_google_drive_token.py
   ```
   ※スコープを追加した場合は、トークンを再取得する必要があります

---

## 注意事項

- このコマンドは、Google Calendar APIとGoogle Drive APIの両方が有効化されている必要があります
- Google Calendar APIが設定されていない場合は、手動でカレンダーの予定を入力することもできます
- 生成されたスケジュールは提案であり、状況に応じて柔軟に調整してください
- タスクの優先順位や認知負荷の評価は、AIによる推定です。最終的な判断はユーザーが行ってください
