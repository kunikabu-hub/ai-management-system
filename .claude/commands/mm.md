# /mm — 商談記録の取り込み

Circleback に溜まった商談記録を Notion に流し込む。**記録はあるがNotionに入っていない、という状態を解消するのが目的。**

入力: `$ARGUMENTS`（省略時は**直近7日間**）

---

## 進め方の原則：途中で止まらない

判断は自分で下し、結果を STEP 6 でまとめて報告する。止まってよいのは **Notion が実際にエラーを返したとき**だけ。

**「結果が0件」はエラーではない。** 議事録DBが空なのは初回なら当然で、そこで止まらない。止まるのは HTTPエラー・認証失敗・404 のように**応答そのものが得られなかった場合**に限る。ここを取り違えて何も登録せずに終わった失敗が実際にある。

ただし**自動生成した記録は確定扱いにしない。** 会食や雑談混じりの会議では抽出精度が落ちる。人が週次で確認するまでは下書きとして扱う。

---

## STEP 1. Circleback から会議を取る

**REST API を curl で叩く。** APIキーは環境変数 `CIRCLEBACK_API_KEY` に入っている（コックピットが渡す）。**キーを画面やファイルに書き出さない。**

```bash
curl -s -H "Authorization: Bearer $CIRCLEBACK_API_KEY" \
  "https://circleback.ai/api/meetings?limit=20"
```

`claude.ai` の Circleback コネクタ（`SearchMeetings` 等）は**このCLIからは見えない**。使えるのは REST API だけ。

**1回のリクエストで必要なものが全部返る。** 会議ごとに詳細を取り直す必要はない。

| 項目 | 中身 |
|---|---|
| `id` `name` `createdAt` `duration` | 会議の識別と日時 |
| `notes` | `####` 見出し付きの構造化要約（概要＋詳細セクション） |
| `attendees` | `[{name, email}]` |
| `actionItems` | `[{title, description, assignee:{name,email}, status}]` |
| `url` | 会議URL（`meet.google.com` など） |
| `tags` `insights` `privateNotes` `recordingUrl` | 補助情報 |

**応答が大きいので、必要な項目だけに絞ってから扱う。** 生のJSONをそのまま読み込むとコンテキストを食い潰す。

```bash
curl -s -H "Authorization: Bearer $CIRCLEBACK_API_KEY" \
  "https://circleback.ai/api/meetings?limit=20" | python3 -c "
import sys,json
for m in json.load(sys.stdin):
    if m['createdAt'][:10] < '2026-08-25': continue
    print(json.dumps({k:m.get(k) for k in
      ('id','name','createdAt','notes','attendees','actionItems','url')}, ensure_ascii=False))
"
```

**作業用の中間ファイルは `/tmp` に置く。`output/` に書かない。** `output/` は成果物の置き場で、そこに置いたものは Google Drive にも流れる。

期間で絞る場合は `createdAt` で自分でフィルタする。引数が会議名の一部なら `name` で絞る。

**注意: `attendees` で相手の氏名が取れないことがある。** Circleback が識別できない参加者は `Participant 1` で `email` が `null` になる。**相手の氏名は会議名と `notes` の本文から拾う**（例: 会議名「PIC河村さんMTG」→ 河村さん）。

## STEP 2. Notion の現状を読む

`notion-eigyo` サーバを使う。ID は CLAUDE.md の表から引く。

- **議事録DB**（`28299f3c-ed1f-460b-b05a-91650044f885`）— **同じ会議が既に入っていないか**を日付＋タイトルで確認する。重複登録しない
- **クライアントマスタ** — 相手が登録済みか
- **提案トラッキング / 拡張案件** — 関連する案件があるか

読み取りに失敗したら**そこで止めて報告する。CLAUDE.md の記述で代用しない。**

## STEP 3. 議事録DBへ登録する

会議1件につき1レコード。既に同じ会議があればスキップする。

| 列 | 入れるもの |
|---|---|
| タイトル | 会議名。末尾に `（自動生成）` を付ける |
| 日付 | `createdAt` の日付部分 |
| クライアント | クライアントマスタへのリレーション（STEP 4 で作った先も含む） |
| チャネル | 会議URLから判定。`meet.google.com` は選択肢に無いため **Zoom** を使わず、判定できない場合は空欄にして STEP 5 で報告する |
| 参加者 | `attendees` の氏名＋本文から拾った相手の氏名 |
| 決定事項 | `notes` の「概要」から、**決まったこと**だけを抜く。検討中の話を決定として書かない |
| 宿題_自社 | `actionItems` のうち assignee が `@ehon.inc` / `@attadesign.co.jp` のもの |
| 宿題_先方 | それ以外の actionItems と、本文中の先方待ちの事項 |
| 次アクション期日 | 本文に期日があれば入れる。無ければ空欄 |
| 温度感 | 高／中／低 を本文から判断する。**先方が難色を示したものを「中」に丸めない** |

## STEP 4. 未登録の相手をクライアントマスタに追加する

会議の相手がクライアントマスタに無ければ新規作成する。

- ステータス: **相談レベル**
- 相手区分: 会話内容から判断（顧客／代理店／パートナー／ネットワーク）
- 接点の起点: 分かれば。不明なら「不明」
- 紹介者: **本文から分かれば必ず入れる。受注の8割が紹介なので、ここが最重要**
- 備考: 何を話し、どう反応したかを200字以内。先頭に `【YYYY-MM-DD 更新】`

**既にある場合は備考欄に追記する。上書き禁止。**

## STEP 5. 既存案件へ追記する

会議が既存の提案・拡張案件に関係していれば、**次アクション欄に追記**する。

- 先頭に `【YYYY-MM-DD 更新】` を付ける
- **追記のみ。上書き禁止。** 次アクション欄には長期の検討メモが蓄積されており、機械が消すと事故になる
- 期日が動いたなら次アクション期日も更新する

## STEP 6. 報告する

### 既存レコードを変更しない（重要）

**既存行の「ステージ」「金額」「提案名」を書き換えてはならない。** これらは売上見込みとKPIの根拠になる数値で、自動処理が動かすと、パイプラインが誰にも気づかれないまま増減する。実際に、商談中だった案件が受注に変わり、進行中の総額が数百万円動いた事故が起きている。

やってよいのは次だけ。

- **次アクション欄への追記**（先頭に `【YYYY-MM-DD 更新】`、上書き禁止）
- **次アクション期日の更新**（期日が動いたことが明確な場合）
- **納品状況の更新**（受注済み案件の進捗）
- **新規行の作成**

ステージを進めるべき／金額が変わったと判断した場合は、**変更せずに報告へ書く**。

```
【ステージ変更の提案】元気だ米絵本 印刷：商談中 → 受注
  根拠: 8/26のMTGで第2期特典としての配布に概ね合意
  留保: 印刷見積もりは未着（8/26依頼・月曜到着予定）。発注確定はまだ
```

受注の判定は「合意した」ではなく「**発注が確定した**」。ここを緩めると見込みが実態から離れる。


1. **登録した会議** — 何件、どの会議。スキップした重複も挙げる
2. **新規登録した相手** — 何社。それぞれ何の話だったか1行
3. **追記した案件** — どの案件に何を足したか
4. **判断に迷った点** — チャネルが判定できなかった、相手の氏名が推定、温度感の根拠が薄い、など。**ここを省かない**
5. **人が確認すべきもの** — 会食・雑談混じりで抽出が怪しい会議

---

## 外しやすい前提

- **相手の氏名を attendees だけで判断する** — 取れないことが多い。本文と会議名を必ず読む
- **検討中の話を決定事項として書く** — 「〜を検討」「〜の方向」は決定ではない
- **難色を温度感「中」に丸める** — 先方が否定的なら「低」と書く。良く見せると次の判断を誤らせる
- **重複登録** — 同じ会議を2回入れると件数が狂う。日付＋タイトルで必ず照合する
