# agent-memory

会話から重要な情報を抽出し、長期記憶として保存します。

## 実行内容

このコマンドは、以下のステップで会話内容を構造化して保存します：

1. **会話から保存すべき情報を抽出**
2. **適切なカテゴリに分類**
3. **00_context/memories/ 配下の適切なファイルに追記**
4. **保存内容をユーザーに報告**

---

## ステップ1: 会話から保存すべき情報を抽出

直近の会話内容を分析し、以下のような情報を抽出します：

### 抽出すべき情報の種類

#### 1. 意思決定とその理由
- 事業戦略の決定事項
- プロジェクトの方向性
- 採用・不採用の判断
- 優先順位の変更

**例**:
```
意思決定: ペット絵本の開発を優先する
理由: 市場のニーズが高く、競合が少ない。B2Cの新規顧客獲得につながる
日付: 2026-02-12
```

#### 2. ユーザーの個人的な好み・方針
- 仕事のスタイル
- コミュニケーションの好み
- ツールの選好
- デザインの好み
- 文体・トーンの好み

**例**:
```
好み: 提案資料は箇条書き中心で、ビジュアルは最小限
理由: 意思決定者が忙しく、短時間で要点を把握したい
```

#### 3. 事実情報・データ
- プロジェクトの具体的な数値（予算、期限、KPI）
- 取引先・パートナーの情報
- 技術スタック・ツールの選定
- 顧客からのフィードバック
- 市場調査の結果

**例**:
```
事実: 鈴木自工との契約
- 導入開始日: 2026年4月1日
- 契約内容: 購入車両のアバター絵本
- 担当者: 山田さん
```

#### 4. 学びや気づき
- 試行錯誤の結果
- 失敗から学んだこと
- 成功パターン
- ベストプラクティス

**例**:
```
学び: かんぽインタビューでは、ユーザーの感情データを物語化することに強い興味を示した
気づき: 高齢者向けの終活絵本は、感情データの活用がキーになる可能性
```

#### 5. 重要な会話・やりとり
- クライアントとの重要な合意
- チーム内の重要な議論
- フィードバックの内容

**例**:
```
会話: ナックとの提案MTG（2026-02-10）
内容: 代理店販売契約について、15%還元で合意。次回は契約書のドラフトを確認
```

## ステップ2: 適切なカテゴリに分類

抽出した情報を以下のカテゴリに分類します：

### カテゴリ一覧

| カテゴリ | ファイル名 | 内容 |
|---------|-----------|------|
| **意思決定** | `decisions.md` | 事業戦略、プロジェクトの方向性、重要な判断 |
| **個人的な好み** | `preferences.md` | 仕事のスタイル、ツールの選好、デザインの好み |
| **プロジェクト情報** | `projects.md` | 進行中のプロジェクト、契約内容、担当者情報 |
| **顧客・パートナー** | `stakeholders.md` | 取引先、パートナー、顧客の情報 |
| **学び・気づき** | `learnings.md` | 試行錯誤の結果、成功パターン、ベストプラクティス |
| **市場・トレンド** | `market_insights.md` | 市場調査、競合分析、業界トレンド |
| **技術・ツール** | `tech_stack.md` | 技術スタック、ツール選定、システム構成 |
| **その他** | `misc.md` | 上記に該当しない重要な情報 |

### 分類の判断基準

1. **複数のカテゴリに該当する場合**: メインのカテゴリに保存し、他のカテゴリには参照リンクを追加
2. **カテゴリが不明な場合**: `misc.md` に保存し、後で整理
3. **既存の情報と重複する場合**: 既存の情報を更新（上書きではなく、日付付きで追記）

## ステップ3: 00_context/memories/ 配下の適切なファイルに追記

情報を適切なファイルに追記します。

### ファイル形式

各ファイルは以下の形式で管理します：

```markdown
# [カテゴリ名]

**最終更新**: YYYY-MM-DD

---

## [サブカテゴリ or 日付]

### [タイトル] (YYYY-MM-DD)

**内容**:
[詳細な内容]

**関連情報**:
- [関連するファイルや情報へのリンク]

**タグ**: #タグ1 #タグ2 #タグ3

---
```

### 実行内容

1. **ファイルの存在確認**:
   - `00_context/memories/` ディレクトリ内のファイルを確認
   - 該当するカテゴリのファイルが存在しない場合は新規作成

2. **情報の追記**:
   - 既存のファイルの末尾に新しい情報を追加
   - 日付とタイトルを明記
   - 関連情報やタグを追加

3. **重複の確認**:
   - 同じ内容が既に保存されていないか確認
   - 重複がある場合は、更新または統合

### 例: decisions.md への追記

```markdown
# 意思決定

**最終更新**: 2026-02-12

---

## ペット絵本の開発優先 (2026-02-12)

**決定内容**:
ペット絵本の開発を優先し、次の四半期の主要プロジェクトとする

**理由**:
- 市場のニーズが高く、競合が少ない
- B2Cの新規顧客獲得につながる
- AIアバター生成技術を活用できる

**期待される効果**:
- 月間売上目標: 100万円（初月は30万円）
- 新規顧客獲得: 200名/月
- ペット業界との新規パートナーシップ

**関連情報**:
- [ペット絵本企画書](../03_projects/pet_picture_book/)
- [市場調査レポート](../output/trends/pet_market_2026.md)

**タグ**: #意思決定 #ペット絵本 #B2C #優先順位

---
```

## ステップ4: 保存内容をユーザーに報告

保存した情報をユーザーに報告します。

### 報告内容

1. **保存した情報の概要**
2. **保存先のファイル**
3. **カテゴリ分類**
4. **関連情報へのリンク**

### 報告フォーマット

```markdown
## 💾 記憶に保存しました

### 保存した情報

#### 1. [タイトル]
- **カテゴリ**: [カテゴリ名]
- **保存先**: `00_context/memories/[ファイル名].md`
- **内容**: [簡潔な要約]
- **タグ**: #タグ1 #タグ2

#### 2. [タイトル]
- **カテゴリ**: [カテゴリ名]
- **保存先**: `00_context/memories/[ファイル名].md`
- **内容**: [簡潔な要約]
- **タグ**: #タグ1 #タグ2

### 📁 保存先ファイル
- `00_context/memories/decisions.md` (更新)
- `00_context/memories/projects.md` (更新)
- `00_context/memories/learnings.md` (新規作成)

### 🔍 次回からの活用
これらの情報は、今後の会話や意思決定の際に自動的に参照されます。

**関連情報の確認**:
- `00_context/memories/` ディレクトリ内のファイルを確認してください
- 必要に応じて手動で編集・整理することもできます
```

## 使い方

### 基本的な使い方

```bash
# Claude Code CLIで実行
/agent-memory

# または
claude run agent-memory
```

### ユーザーからのトリガー

以下のようなフレーズをユーザーが言った場合、このスキルを発動します：

- 「覚えておいて」
- 「記憶して」
- 「保存して」
- 「メモして」
- 「重要な情報として記録して」

### 自動発動のタイミング

以下のような会話があった場合、AIは自発的にこのスキルを提案します：

1. **重要な意思決定が行われた後**
   - 「〇〇を優先することに決めました」
   - 「〇〇は見送ることにします」

2. **プロジェクトの重要な情報が共有された後**
   - 「鈴木自工との契約が決まりました」
   - 「ナックとの提案が通りました」

3. **ユーザーが好みや方針を明示した後**
   - 「資料は箇条書き中心で作ってください」
   - 「朝一番はメールチェックから始めたい」

4. **重要な学びや気づきがあった後**
   - 「かんぽインタビューで〇〇がわかりました」
   - 「この方法は効果的でした」

## 保存された情報の活用

保存された情報は、以下のように活用されます：

1. **コンテキストの維持**:
   - 長期的な会話の中で、ユーザーの好みや方針を反映
   - 過去の意思決定を踏まえた提案

2. **一貫性のある対応**:
   - 同じ質問に対して一貫した回答
   - ユーザーのスタイルに合わせた資料作成

3. **効率的な作業**:
   - プロジェクト情報を毎回聞く必要がない
   - 過去の学びを活かした提案

4. **戦略的な意思決定**:
   - 過去の決定を踏まえた新しい提案
   - トレンドや市場情報の蓄積

---

## 情報の整理・メンテナンス

### 定期的な整理

月に1回程度、以下の作業を行うことを推奨します：

1. **重複情報の統合**
2. **古い情報の更新または削除**
3. **カテゴリの再分類**
4. **タグの整理**

### 整理のためのコマンド（今後実装予定）

```bash
# 記憶の一覧を表示
/agent-memory list

# 特定のカテゴリの記憶を表示
/agent-memory list --category decisions

# 特定のタグで検索
/agent-memory search --tag ペット絵本

# 記憶の編集
/agent-memory edit decisions.md
```

---

## 注意事項

1. **機密情報の取り扱い**:
   - 個人情報や機密情報は、適切に管理してください
   - 必要に応じて、特定の情報は保存しないように指示できます

2. **情報の正確性**:
   - 保存される情報は、AIによる解釈が含まれます
   - 重要な情報は、保存後に必ず確認してください

3. **ストレージ管理**:
   - 情報が蓄積すると、ファイルサイズが大きくなります
   - 定期的に整理し、不要な情報は削除してください

4. **バージョン管理**:
   - `00_context/memories/` はGitで管理することを推奨
   - 誤って削除した場合も復元可能です
