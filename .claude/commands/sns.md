# /sns — SNS投稿の下書きを積む

**中間ファイルを `output/` に書かない。** `output/` は提案書の置き場で、そこに置いたものは Google Drive にも流れる。作業ファイルが要るなら `/tmp` に置く。

**投稿はしない。下書きを積むところまで。** 承認は必ず人が行う。参照モデルの鈴木氏自身が「完全自動化には反対」と述べており、この設計はそれに合わせている。

入力: `$ARGUMENTS`（省略時は **note 3本 ＋ X 5本**）

---

## 進め方の原則：途中で止まらない

題材の選定・切り口・文面はすべて自分で決めて進む。止まってよいのは **Notion の読み書きが実際にエラーを返したとき**だけ。**「結果が0件」はエラーではない。**

## STEP 1. 素材を集める

`notion-eigyo` を使う。ID は CLAUDE.md の表から引く。

1. **企画・アイデア・課題DB**（`709c83b0-c4c5-45c3-8b88-f2471af670c0`）— **`SNS化` にチェックが入っているものが第一候補**。`学び・結果` に数字が入っているものは特に強い
2. **SNS投稿キュー**（`410a0a40-fd05-4dd0-81c9-897c62d0b7dd`）— **直近に何を投稿したかを見て、題材と切り口を重複させない**
3. 提案トラッキング・議事録 — 直近の納品事例や商談での気づき

## STEP 2. 媒体ごとに書き分ける

**noteが主力、Xは従。** 参照モデルの実測では、流入の主力はXではなく note（毎日級の記事量産）と PR TIMES（月20本）で月90〜110件の問い合わせ。**note記事を先に作り、人気が出たものだけXへ展開する**順で設計する。

### note
- 1,500〜2,500字。見出しを3〜4本立てる
- **具体の数字と固有名詞を入れる**。「木桶」「蔵付き微生物」「信長の兵糧」のような固有名詞が効く。抽象語だけの記事は読まれない
- 結論を先に置き、経緯を後から説明する

### X
- 140字以内。1投稿1メッセージ
- **生成臭が強いとスルーされる。テキストのみの簡素な版を必ず混ぜる**。装飾・絵文字・箇条書きを詰め込まない
- 予定日は閲覧ピークに寄せる — **火・木 19〜20時、土日 22〜23時**

### Instagram
- 指定があったときだけ作る。ビジュアルが要るため優先度は低い

## STEP 3. 語り方の規律

**実体験ではなく「知人・お客様事例」として語る。** NoaÉre Pre の既定方針であり、全媒体に適用する。「私が体験した」ではなく「お客様が」「知人が」の主語で書く。

**数字は出典のあるものだけ使う。** 使ってよい実測値は次のとおり。

- ガリバー成約特典アンケート：楽しんだ約90%／ブランド親しみ増52.9%／再来店意向29.4%／回答者の78.6%が子なし層
- JAPAN MOBILITY SHOW 2025：6日間でLINE新規4,000件
- おみくじガチャ：開始1週間で600〜700回

**書いてはいけないもの**

- **顧客の取引額・請求額**（「鈴木自工 累計売上2,572,350円」のような記述）
- 粗利率・粗利額
- FC100店舗モデル 年間粗利264万円（仮置きで根拠が固まっていない）
- **代理店経由の顧客名**を許可なく出すこと（芋慶・THE BALLET SHOW → グローバルパートナーズ／アテニア → DNP）。未確認なら「大手生命保険会社」「バレエ公演主催者」のような業種表記にする
- **未確定の企画を確定のように書くこと**。Gene Story Book は実績ゼロでPoCがこれから

## STEP 3.5 保存前の自己点検（1件ずつ全文を読み返す）

書き終えたら、**1件ずつ本文を頭から読み直して**次を確認する。実際に違反した下書きが生成された事故がある。

**① 数字を1つずつ指さして確認する**

本文に出てくる数字を全部拾い、次のどれかに該当したら**その文ごと削除する**。言い換えでは残さない。

- 粗利率・粗利額（「43.6%」「79.5%」など）
- 顧客の取引額・累計売上（「累計1,125万円」「売上の41.3%」など）
- 他社の請求額・原価・仕入値

**発注先を名指しで比較しない。** 「石川特殊特急製本は43.6%、錦明印刷は79.5%」のような書き方は、取引先との関係を壊す。印刷会社・外注先の優劣を公開の場で語らない。

**② 主語を確認する**

「試した」「やってみた」「実施した」が主語なしで出ていたら書き直す。**「お客様が」「知人の会社が」「ある販売店で」**が正しい主語。

**③ 顧客名を確認する**

代理店経由の顧客名（芋慶・THE BALLET SHOW → グローバルパートナーズ／アテニア → DNP）が出ていたら、業種表記に置き換える。

**④ 未確定を確定として書いていないか**

Gene Story Book は実績ゼロでPoCがこれから。「成果が出た」と書かない。

## STEP 4. キューに積む

SNS投稿キューに1件1レコードで作成する。

| 列 | 入れるもの |
|---|---|
| 投稿文 | 一覧で見分ける短い要約（40字以内）。全文ではない |
| 本文 | **実際に投稿する全文をここに入れる。** 要約や「完全版は別ファイル」で済ませない。noteの長文もそのまま入れる（Notionのテキスト欄は2,000字まで／超える場合は本文欄に冒頭を入れ、続きをページ本文に書く） |
| 媒体 | note / X / Instagram |
| ステータス | **必ず `下書き`**。承認済にしない |
| 切り口 | 事例紹介／制作の裏側／業界の話／価値観・想い／データ・知見／告知 |
| 予定日 | Xは閲覧ピークに寄せる。noteは平日午前 |
| 元ネタ | 企画・アイデア・課題DBへのリレーション |

**切り口を偏らせない。** 事例紹介ばかりが並ぶと宣伝に見える。制作の裏側・業界の話・価値観を混ぜる。

## STEP 5. 報告する

1. **何本作ったか**（媒体別）
2. **どの素材から作ったか** — 企画DBのどのレコードを使ったか
3. **避けた題材と理由** — 直近と重複、数字の裏が取れない、代理店の許可が未確認、など
4. **承認時に見てほしい点** — 事実関係が怪しい箇所、表現を選んだ意図

---

## 外しやすい前提

- **実体験として書いてしまう** — 主語は「お客様」「知人」
- **裏の取れない数字を書く** — 出典のある実測値だけを使う
- **事例紹介ばかりになる** — 宣伝色が強いと読まれない
- **同じ題材を繰り返す** — キューの直近を必ず確認する
- **Xを主力として設計する** — noteが先、Xは人気記事の展開先
